# Current schema inventory

## Scope and source

This inventory freezes the schema currently expected by the JPA mappings on branch `feature/#181-flyway-foundation`.

- Source of truth: the 50 JPA entities and their embeddables/element collections under `src/main/java`.
- SQL realization: Hibernate 6.6 `MySQLDialect`, normalized into `V1__baseline_current_schema.sql`.
- Application tables: 54. Flyway's `flyway_schema_history` is created separately by Flyway.
- Every column has no explicit SQL `DEFAULT` unless a different value is shown below. Java field initializers are not database defaults.
- `NULL` below means the JPA mapping does not declare `nullable = false`; it does not imply that the domain accepts null.
- Constraint names beginning with `UK` or `FK` are Hibernate-generated names frozen by V1.

## Entity-to-column naming review candidates

These are inventory findings only; V1 intentionally preserves them and does not change behavior.

- `QuestTitle.value` declares `@Column(name = "titleId")`; the physical naming strategy produces `quests.title_id`. Despite the `_id` suffix, it is a quest-title string, not a foreign key.
- `Player` maps to singular table `player`, while most aggregate tables are plural.
- `Certification` maps explicitly to singular table `certification`.
- `Guild.playerId` / `Party.playerId` and `leaderPlayerId` produce both `player_id` and `leader_player_id`; neither is a JPA relationship or database foreign key.
- Many cross-aggregate IDs (for example `item_id`, `player_id`, `quest_id`, `title_id`) are intentionally scalar IDs. V1 adds foreign keys only where the current JPA mapping declares an association.
- `Player.statusEffects` has no explicit `@Column`; the physical name is `status_effects` and the converter-backed storage type is `varchar(255)`.
- `PlayerHobby` does not extend `AbstractTime`, so `player_hobbies` has no `created_at` or `updated_at` columns.

## V1 interpretation

V1 is a clean-install schema snapshot, not an upgrade script. It contains no `DROP`, destructive `ALTER`, data rewrite, or automatic baseline behavior. Existing databases must be compared semantically and baselined manually according to `docs/database/flyway_baseline_runbook.md`.
