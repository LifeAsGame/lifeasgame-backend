1. QuickRecord -> LifeLogRecorded: VERIFIED
Production: QuickRecordService dispatches to existing subtype services, reserves/completes V9 receipt, and LifeLogRecordRegistrar writes the V15 canonical header while TransactionalOutboxDomainEventPublisher appends the fact. Evidence: QuickRecordServiceIntegrationTest proves subtype creation, canonical metadata, sequential/concurrent replay, payload conflict, and rollback; LifeLogRecordedOutboxIntegrationTest proves source/fact commit and rollback.

2. LifeLogRecorded -> Quest progress: VERIFIED
Production: LifeLogRecordedQuestTrigger accepts content-ready owned facts and QuestSignalProcessingAttempt uses durable V7 receipts. Evidence: LifeLogRecordedQuestProgressIntegrationTest proves acceptance time boundaries, multi-Quest progress, replay with alternate eventId, concurrent duplicate exactly once, and weekly exact-period policy.

3. Quest -> completion: VERIFIED
Production: QuestAcceptance transition rules and Quest transition/completion factories append facts through V8. Evidence: QuestCompletionRewardTransactionalOutboxIntegrationTest#completesActualLifeLogAutoClosedLoop and #completesActualManualCheckClosedLoop start from actual LifeLog/manual commands and reach completion.

4. completion -> RewardSettlement: VERIFIED
Production: typed QuestRewardReadyFact and QuestCompletionRewardService create V3 settlement/lines. Evidence: QuestCompletionRewardTransactionalOutboxIntegrationTest proves RP_NONE, EXP, EXP+ITEM, duplicate delivery, failure persistence, and profile snapshot conflict.

5. EXP -> Player growth: VERIFIED
Production: PlayerRewardExpGrantService locks Player and records V4 player_growth_changes by reward line. Evidence: QuestCompletionRewardTransactionalOutboxIntegrationTest proves exact-once EXP; GrowthQueryIntegrationTest proves bounded current-player provenance reads.

6. ITEM -> Mailbox: VERIFIED
Production: InventoryRewardDeliveryApi is provider-owned, joins the caller transaction, resolves stable ItemCode, locks Mailbox, and saves V17 receipt. Evidence: InventoryRewardDeliveryIntegrationTest proves stable payload, stacking, sequential/concurrent replay, full-mailbox rollback, and caller rollback; the actual three-LifeLog loop proves the P0 item.

7. Mailbox claim -> Inventory: VERIFIED
Production: MailboxService locks Mailbox and Inventory, preflights the whole batch, then applies both mutations in one transaction. Evidence: MailboxClaimIntegrationTest proves single/all claims, attrs/bound preservation, merge/new stack, and rollback on late quantity/item/capacity failures.

8. Quest completion -> Notification: PARTIALLY_VERIFIED

Missing: one real Quest completion -> relay -> player_notifications integration scenario.

11. explicit Route advance: VERIFIED
QuestRouteAdvanceService requires expectedStepId, locks the player route, evaluates required completion evidence, and advances one step. QuestRouteApplicationIntegrationTest proves unsatisfied rejection, one-step transition, stale replay rejection, concurrent maximum-one transition, and final completion.

13. Notification append -> inbox/unread/read: VERIFIED
NotificationAppender, NotificationQueryService, and NotificationReadMarker use V25. NotificationApplicationIntegrationTest proves durable and concurrent source replay, per-player scoping, newest-first cursor pagination, idempotent single read with ownership hiding, mark-all isolation, and unread-state updates.

ListingOpenService uses InventoryMarketAvailabilityApi and whole-entry snapshots. MarketplaceReservationConcurrencyIntegrationTest proves Listing locking and the V27 active reservation invariant. MarketplaceTradeFulfillmentIntegrationTest proves Listing SOLD, reservation CONSUMED, hold COMMITTED, seller proceeds, seller removal, buyer fulfillment, V28 Trade snapshot, and full rollback on buyer capacity failure in one transaction.
